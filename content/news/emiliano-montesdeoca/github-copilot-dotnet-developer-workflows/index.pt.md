Acho que uma das mudanças mais úteis na adoção do Copilot é sair da obsessão por recursos.

É exatamente por isso que este novo **guia do GitHub Copilot para desenvolvedores .NET** funciona tão bem.

A grande ideia é simples: pare de perguntar qual modo do Copilot é mais legal e comece a perguntar **qual superfície combina com a tarefa**.

## Este é o modelo mental certo

Para a maior parte do trabalho real em .NET, a pergunta não é:

- chat ou agent?
- Visual Studio ou CLI?
- inline ou cloud?

A pergunta melhor é:

- estou tentando entender código?
- estou planejando um refactor?
- estou atualizando testes?
- estou corrigindo um build quebrado?
- estou coordenando uma mudança que toca vários arquivos?

Isso é muito mais produtivo ao trabalhar com Copilot.

## A frase mais útil do artigo original

A linha que eu destacaria do post original é esta:

> "**A pergunta não é qual é o mais avançado. A pergunta melhor é: qual combina com o trabalho que estou fazendo agora?**"

Esse é exatamente o conselho que eu daria também.

Porque muita confusão em ferramentas de IA vem de tratar superfícies como identidades, em vez de ferramentas.

Visual Studio, VS Code, CLI e agentes em segundo plano se encaixam em momentos diferentes.

E, uma vez que você aceita isso, toda a experiência fica muito mais prática.

## Por que isso importa especialmente para times .NET

O trabalho em .NET frequentemente cobre vários tipos de tarefas em um único dia:

- entender um serviço legado
- planejar um refactor
- gerar testes
- corrigir um build quebrado
- mexer em code, config, docs e infrastructure ao mesmo tempo

Isso significa que nenhuma superfície do Copilot será a melhor para tudo.

Por isso o conselho deste guia é bom, porque reflete como o trabalho realmente acontece.

## Minha opinião

Este guia é útil porque trata o Copilot como parte do loop real de desenvolvimento .NET, em vez de uma camada de novidade por cima dele.

Isso o torna relevante.

E, sinceramente, mais guias de IA melhorariam muito com esse mesmo deslocamento para o pensamento task-first.
