Расширение MSSQL для VS Code растёт уже давно, но это последнее обновление делает направление намного яснее.

Это уже не просто «подключись и запусти несколько запросов».

С **Azure SQL provisioning**, **Schema Designer с Copilot**, **SQL Notebooks** и **Data API builder**, продвигаемыми в одном релизе, расширение становится гораздо более полноценной рабочей средой для разработки, связанной с базами данных.

## Практический крючок — provisioning прямо из редактора

В исходной статье говорится, что теперь можно создать полностью управляемую облачную базу данных «прямо из редактора и без затрат», используя бесплатный уровень.

Это та функция, которая кажется небольшой, пока не понимаешь, сколько friction при настройке она убирает.

Для многих разработчиков неприятная часть экспериментов с большим объёмом данных — не SQL как таковой. Это разрыв между:

- идеей
- базой данных
- схемой
- API
- тестируемым backend

Если этот разрыв сокращается внутри одного инструмента, весь workflow становится привлекательнее.

## Вот как выглядит более сильный inner loop для работы с данными

Мне нравится в этом релизе то, что он держит больше частей workflow базы данных в одном месте:

- provisioning базы данных
- проектирование схемы
- просмотр изменений
- генерация ORM-скриптов
- предоставление API
- тестирование endpoints
- документирование и запросы через notebooks

Это гораздо более убедительная история, чем воспринимать SQL как отдельный боковой инструмент в стеке.

## Workflow схемы с поддержкой Copilot — это место, где ценность ИИ ощущается по-настоящему

Добавления в schema designer особенно интересны, потому что они, похоже, находят хороший баланс.

Ценность не в том, что «ИИ проектирует вашу модель данных, а вы слепо доверяете».

Ценность в следующем:

- более быстрые стартовые точки
- визуальный review
- отслеживание изменений
- вывод, ориентированный на миграцию
- явные controls accept/undo

Это гораздо более здоровый AI workflow, чем полная auto-generation без пути инспекции.

А в работе с базами данных возможность review очень важна.

## Data API builder — тихий множитель

Другая функция, которую я бы не игнорировал, — интеграция Data API builder.

Если вы можете перейти от схемы к:

- REST
- GraphQL
- MCP endpoints

внутри одной и той же среды, это создаёт очень эффективный путь для backend-прототипов и внутренних инструментов.

Это не заменяет более глубокую backend-инженерию. Но это заметно сокращает путь от идеи базы данных до работающего интерфейса.

Этот релиз заставляет расширение MSSQL ощущаться скорее как маленькая платформа внутри VS Code, чем как простой add-on.

Для разработчиков, создающих API, data tools, admin tools или SQL-backed prototypes, это значимое изменение.
