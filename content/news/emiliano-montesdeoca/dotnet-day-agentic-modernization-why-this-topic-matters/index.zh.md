我认为 **代理式现代化** 这个说法会留下来。

不是因为它很流行，而是因为它描述了很多团队现在真正想做的事：在不假装可以把所有东西都丢掉重新开始的前提下，现代化现有的 .NET 系统。

这就是为什么即将到来的 **.NET Day on Agentic Modernization** 吸引了我的注意。

没错，这是一个活动公告。但当活动能揭示平台讨论的走向时，它们就变得有趣，而这个活动显然做到了这一点。

## 旧的现代化叙事已经不够了

多年来，现代化讨论通常围绕迁移目标展开：

- 上云
- 升级框架
- 拆分单体
- 把应用容器化

这些仍然都很重要。

但现在团队也在问：

- AI 在系统中该放在哪里？
- 如何把 copilot 或 agent 带入现有工作流？
- 如何现代化开发者体验，而不只是运行时托管？
- 如何在不重写整个业务的情况下使用 Aspire 和 Foundry 这样的工具？

这是另一种对话，而且说实话要有用得多。

## 为什么这个活动主题显得正合时宜

直播里列出的 session 主题把故事讲得很清楚：

- 使用 GitHub Copilot 辅助现代化
- 让 Aspire 充当现代化桥梁
- 迁移现有的 WinForms 和 line-of-business 应用
- 在迁移后加入代理式功能

这才是正确的操作顺序。

如今的务实思路不再是“AI 取代你的应用”，而是“AI 成为现代化路径中的一种能力，并且尊重你已经拥有的应用”。

我更信任这种思路。

## 对 .NET 团队来说最有意思的部分

对 .NET 开发者来说，这里的最大机会不是抽象的转型语言，而是**带来实际回报的渐进式现代化**。

你可以现代化托管模型。

你可以改进开发者工作流。

你可以在合适的地方加入 agent-driven 功能。

你可以使用云原生工具来降低运维痛苦。

这比“全部重写成 AI-native”更容易让人接受。

## 我的看法

这个活动之所以重要，是因为它捕捉到了认真做 .NET 的团队正在往哪里走。

未来不只是迁移。它是自动化 + 现代化，copilot + 现代化，agent + 现代化，更好的本地和云工具 + 现代化。

这种组合比喻更接近团队真正做的工作。

所以没错，这是一个直播公告。但它也是一个有用的信号，说明 .NET 生态接下来会把重点放在哪里。
