المصدر الأصلي: [Compose your API surface with Data API builder custom paths](https://devblogs.microsoft.com/azure-sql/data-api-builder-custom-rest-paths/)

دعم المسار المركب الجديد في Data API Builder قد يبدو كتحسين بسيط في التكوين، لكنه في الواقع يحل توترًا طويل الأمد في تصميم API: تسرب طوبولوجيا قاعدة البيانات إلى تصميم نقطة النهاية العامة.

المسارات الافتراضية القائمة على الكيانات رائعة للبدايات السريعة. غالبًا ما تكون خاطئة لـ APIs المنتج طويلة الأمد. الأنظمة الحقيقية تحتاج هياكل مسار تطابق مفاهيم الأعمال وحدود الملكية ونماذج المستهلك الذهنية.

لهذا السبب تغيير DAB هذا مهم. يمكنك الاحتفاظ براحة API المولدة مع تقديم سطح موجه للمجال أولاً وأنظف.

رأيي الشخصي بسيط: إذا كانت بنية مسار API الخاص بك تعكس أسماء الجداول الخام في الإنتاج، فأنت عادة ما تحسن لراحة الخلفية على حساب وضوح العميل.

بالمسارات المخصصة، يمكن للفرق نمذجة حدود أفضل، مثل المبيعات والفواتير والدعم أو أسطح خاصة بالشركاء. هذا لا يحل محل حوكمة API المناسبة، لكنه يعطي مستخدمي DAB طريقة عملية لمواءمة تصميم المسار مع لغة المنتج.

إرشادات عملية للفرق التي تتبنى هذه الميزة:

- حدد سياسة تسمية قبل إضافة المسارات بشكل عشوائي. الأقسام الفرعية غير المتسقة تصبح فوضى طويلة الأمد.
- حدد نقاط النهاية لسياقات محدودة، وليس لمخططات تنظيمية. الفرق تتغير؛ دلالات المجال يجب أن تكون مستقرة.
- تعامل مع بنية المسار كجزء من استراتيجية الإصدار الخاص بك ووثق التغييرات الجوهرية صراحة.
- تحقق من سلوك التفويض على طول هياكل المسار المخصصة بحيث يقترن وضوح المسار بوضوح الأمان.

ما أقدره في DAB بشكل عام هو نموذج الرفع: تحصل على التقسيم والتصفية والإسقاط وآليات نقطة نهاية أخرى دون كتابة كود تحكم متكرر. المسارات المخصصة تجعل ذلك الرفع أكثر جاهزية للإنتاج بتقليل أحد أكبر الاعتراضات من مهندسي API.

هناك تحذير واحد. تكوين المسار الأفضل يمكن أن يغري الفرق بكشف الكثير بسرعة لأن التوليد يبدو سهلاً. الحواجز لا تزال مهمة: حافظ على كشف الكيان متعمدًا، طبق السياسة مركزيًا، وتجنب بناء عقود عامة عرضية من تجارب المخطط الداخلية.

لمؤسسات .NET تحت ضغط التوصيل، هذه الميزة هي فتح إنتاجية إذا استُخدمت بانضباط. يمكنك التحرك أسرع من طبقات API المصنوعة يدويًا مع الحفاظ على سطح نقطة نهاية متماسك وصديق للأعمال.

الخلاصة: مسارات DAB المخصصة ليست حول تجميل عناوين URL. إنها حول استعادة نية تصميم API مع الحفاظ على الكفاءة التشغيلية لنقاط النهاية المولدة.
