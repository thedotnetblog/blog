.NET のプレビュー記事は常に情報が満載である。

それはプラットフォームにとって良いニュースだが、実用的な質問が埋もれてしまうことも意味する:**実際に何を最初にテストすべきか？**

.NET 11 Preview 5 は、SDK、ランタイム、ライブラリ、ASP.NET Core、C#、MAUI、EF Core にわたって多くのものを提供している。これを巨大なチェンジログの要約にする代わりに、今すぐ開発者の注意を引くべきだと思う部分に焦点を当てたい。

## `dotnet new` に MCP サーバーテンプレートが含まれたことはシグナルである

これはおそらく SDK セクションの中で最も戦略的な項目である。

プロジェクトテンプレートが SDK に直接組み込まれるとき、それはプラットフォームがもはやそのシナリオをニッチとして扱っていないことを意味する。`dotnet new` に組み込まれた **MCP サーバーテンプレート**は、パターンを試すコストを下げ、エコシステムが向かう方向について明確なメッセージを送る。

.NET でエージェントツール、内部アシスタント、または AI 統合開発者ユーティリティを構築しているなら、これが最初にテストするもののひとつである。

## ビルド時の脆弱性およびサポート終了チェックは、まさに私が好きな種類のデフォルトである

セキュリティとライフサイクル認識は、誰も読まない別個のレポートで後から知らせるよりも、プラットフォームが**ビルド中**に支援する方がはるかに優れている。

ビルド時の脆弱性とサポート終了パッケージの新しい SDK チェックは、私が大好きな種類の機能である。なぜなら、より良い動作をデフォルトにするからだ。

これらは派手ではないが、経年とともによく熟成する種類の改善である。

## C# は引き続き適切な場所でより表現力を増している

Preview 5 の C# 項目は興味深い。特に以下である:

- クローズドクラス階層
- union 宣言と union パターン
- 安全でない進化の継続

プレビュー言語機能は常に冷静なテストサイクルに値するため、本番コードにこれらすべてを盲目的に採用するわけにはいかない。しかし方向性は良い。C# はそのアイデンティティを失うことなく、よりリッチなモデリングへと進み続けている。

## ASP.NET Core と EF Core には早期テストに値する実用的な更新がある

間違いなくスパイクを通すべき2つの領域:

### Blazor の改善

Blazor SSR のクライアントサイド検証と、インタラクティビティなしの QuickGrid 改善は、どちらも実際のアプリを簡素化できる品質向上機能である。

### EF Core のデフォルトと警告

EF Core が SQL Server 2022 互換性をデフォルトにし、同期実行中の非同期 EF クエリに対する警告を追加したことは、まさに実際のコードベースで隠れた問題を表面化できる種類の変更である。

つまり、早期にテストする価値がある。

## 最初に試すべき私の短いリスト

半日かけて Preview 5 を探検するとしたら、以下を行う:

1. MCP サーバーテンプレートを試す
2. ビルドを実行し、新しい脆弱性/EOL チェックを検査する
3. 新しい C# モデリング機能の恩恵を受ける可能性のあるコードベースをテストする
4. そのスタックにいる場合は Blazor SSR シナリオを検証する
5. EF Core 中心のパスを実行し、警告の変更や SQL の違いを監視する

そこに初期の価値があると思う。

## 私の見解

.NET 11 Preview 5 は、プラットフォームが2つの方向に同時に押し進め続けるリリースのひとつに感じられる:

- より野心的な開発者機能
- 本番志向のチームのためのより良いデフォルト

その組み合わせこそ、私がプレビューサイクルに求めるものである。

試してみなさい。ただし目的を持って。
