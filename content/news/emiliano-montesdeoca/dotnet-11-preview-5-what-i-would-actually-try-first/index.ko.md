.NET 프리뷰 포스트는 항상 가득 차 있습니다.

플랫폼에는 좋은 소식이지만, 실용적인 질문이 묻힌다는 것을 의미하기도 합니다: **실제로 무엇을 먼저 테스트해야 할까요?**

.NET 11 Preview 5는 SDK, 런타임, 라이브러리, ASP.NET Core, C#, MAUI, EF Core 전반에 많은 것을 가져옵니다. 이것을 거대한 체인지로그 요약으로 바꾸는 대신, 지금 실제 개발자 관심을 받을 만한 부분에 초점을 맞추고 싶습니다.

## MCP 서버 템플릿이 `dotnet new`에 있는 것은 신호입니다

이것은 아마도 SDK 섹션에서 가장 전략적인 항목일 것입니다.

프로젝트 템플릿이 SDK에 직접 포함될 때, 플랫폼이 더 이상 그 시나리오를 틈새로 취급하지 않음을 의미합니다. `dotnet new`에 내장된 **MCP Server 템플릿**은 패턴을 시도하는 비용을 낮추고 생태계가 어디로 가고 있는지에 대한 명확한 메시지를 보냅니다.

.NET에서 에이전트 툴링, 내부 어시스턴트, 또는 AI 통합 개발자 유틸리티를 구축하고 있다면, 이것이 가장 먼저 테스트할 것 중 하나입니다.

## 빌드 타임 취약점 및 수명 종료 검사는 제가 좋아하는 정확한 종류의 기본값입니다

보안 및 수명 주기 인식은 아무도 읽지 않는 별도 보고서에서 사후에가 아니라, 플랫폼이 **빌드 중에** 도울 때 훨씬 좋습니다.

빌드 중 취약점 및 수명 종료 패키지에 대한 새로운 SDK 검사는 더 나은 행동을 기본값으로 만들기 때문에 제가 사랑하는 기능입니다.

화려하지는 않지만, 시간이 지날수록 정말 잘 노화되는 개선 사항입니다.

## C#는 올바른 곳에서 계속 더 표현력 있게 발전하고 있습니다

Preview 5 C# 항목은 특히 다음에서 흥미롭습니다:

- closed class hierarchies
- union 선언 및 union 패턴
- 계속되는 unsafe 진화 작업

아직 프로덕션 코드에서 이 모든 것을 맹목적으로 채택하지는 않을 것입니다. 프리뷰 언어 기능은 항상 냉정한 테스트 주기가 필요하기 때문입니다. 하지만 방향은 좋습니다. C#는 정체성을 잃지 않으면서 더 풍부한 모델링을 계속 향해 나아가고 있습니다.

## ASP.NET Core와 EF Core에는 일찍 테스트할 가치가 있는 실용적인 업데이트가 있습니다

제가 확실히 스파이크를 통해 확인할 두 영역:

### Blazor 개선

Blazor SSR용 클라이언트 측 유효성 검사와 상호 작용 없는 QuickGrid 개선은 모두 실제 앱을 단순화할 수 있는 삶의 질 기능입니다.

### EF Core 기본값 및 경고

EF Core가 SQL Server 2022 호환성을 기본값으로 이동하고 동기적으로 실행되는 비동기 EF 쿼리에 대한 경고를 추가하는 것은 실제 코드베이스에서 숨겨진 문제를 표면화할 수 있는 정확한 변경 유형입니다.

즉, 가능한 한 빨리 테스트할 가치가 있습니다.

## 첫 번째 패스를 위한 내 짧은 목록

Preview 5를 탐색하는 데 반나절이 있다면, 다음을 할 것입니다:

1. MCP 서버 템플릿 시도
2. 빌드 실행 및 새로운 취약점/EOL 검사 검사
3. 새로운 C# 모델링 기능의 이점을 볼 수 있는 코드베이스 테스트
4. 해당 스택에 있다면 Blazor SSR 시나리오 검증
5. EF Core 중심 경로 실행 및 경고 변경 또는 SQL 차이점 관찰

거기에 초기 가치가 있다고 생각합니다.

## 내 생각

.NET 11 Preview 5는 플랫폼이 두 방향으로 동시에 계속 밀어붙이는 그런 릴리스 중 하나로 느껴집니다:

- 더 야심찬 개발자 기능
- 프로덕션 중심 팀을 위한 더 나은 기본값

그 조합이 제가 프리뷰 주기에서 원하는 것입니다.
