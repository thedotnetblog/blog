A extensão Azure Functions MCP já passou faz tempo da fase de «olha, você pode expor uma ferramenta».

É isso que esta atualização mais recente deixa claro.

Neste ponto, a história ficou muito mais ampla:

- tools
- resources
- prompts
- MCP Apps
- autenticação embutida
- APIs de configuração .NET melhores

E isso muda a forma como vejo a plataforma.

## A extensão está amadurecendo de novidade preview para material de construção real

Os primeiros anúncios de MCP eram principalmente sobre viabilizar o protocolo. Útil, mas ainda bastante cru.

Agora a extensão está crescendo para algo mais completo para equipes com mentalidade de produção:

- suporte mais rico a primitives
- melhor suporte de auth
- conteúdo e schemas estruturados
- configuração .NET mais natural com builder
- um caminho mais claro para integração com Foundry

É isso que você quer ver.

## Por que Azure Functions combina tão bem com MCP

Ainda acho que Azure Functions é uma das opções de hosting mais práticas para servidores MCP remotos.

Você obtém:

- hosting sem servidor
- execução escalável
- padrões familiares de triggers e bindings
- integração embutida de identidade
- boa aderência a superfícies de tool no estilo API

E com a extensão MCP, a distância entre «tenho uma função útil» e «tenho uma superfície de ferramentas descoberta por agentes» continua diminuindo.

## A história do fluent builder em .NET é especialmente boa

As adições em .NET chamaram minha atenção porque continuam a tendência de uma configuração mais expressiva no código.

Poder declarar metadata, schemas, bindings de UI e um comportamento MCP mais rico de forma fluent faz a extensão parecer mais uma ferramenta de desenvolvimento de primeira classe e menos um wrapper fino de protocolo.

Essa é exatamente a direção que eu quero.

## A minha leitura

A verdadeira história aqui não é um recurso isolado. É que a extensão Azure Functions MCP está se tornando uma opção de plataforma realista para equipes que querem hospedar capacidades MCP no Azure sem construir tudo do zero.

E para desenvolvedores .NET, especialmente, a experiência continua melhorando.
