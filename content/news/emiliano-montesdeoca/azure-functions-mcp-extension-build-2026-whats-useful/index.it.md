L'estensione Azure Functions MCP ha da tempo superato la fase del «guarda, puoi esporre uno strumento».

È questo che chiarisce l'ultimo aggiornamento.

A questo punto, la storia è molto più ampia:

- strumenti
- risorse
- prompt
- MCP Apps
- autenticazione integrata
- API di configurazione .NET migliori

E questo cambia il modo in cui vedo la piattaforma.

## L'estensione matura da novità preview a vero materiale da costruzione

I primi annunci MCP riguardavano soprattutto l'abilitazione del protocollo. Utile, ma ancora piuttosto grezzo.

Ora l'estensione sta crescendo in qualcosa di più completo per i team orientati alla produzione:

- supporto più ricco per primitive
- migliore supporto all'autenticazione
- contenuti e schemi strutturati
- configurazione .NET più naturale con builder
- un percorso più chiaro verso l'integrazione con Foundry

È questo che vuoi vedere.

## Perché Azure Functions si adatta così bene a MCP

Continuo a pensare che Azure Functions sia una delle opzioni di hosting più pratiche per server MCP remoti.

Ottieni:

- hosting senza server
- esecuzione scalabile
- pattern di trigger e binding familiari
- integrazione dell'identità incorporata
- buona corrispondenza con superfici di tool in stile API

E con l'estensione MCP, la distanza tra «ho una funzione utile» e «ho una superficie di tool individuabile dagli agenti» continua a ridursi.

## La storia del fluent builder in .NET è particolarmente buona

Le aggiunte .NET hanno attirato la mia attenzione perché continuano il trend verso una configurazione più espressiva nel codice.

Poter dichiarare metadati, schemi, binding UI e un comportamento MCP più ricco in modo fluente fa sembrare l'estensione più uno strumento di sviluppo di prima classe e meno un sottile wrapper di protocollo.

È esattamente la direzione che voglio.

## La mia lettura

La vera storia qui non è una singola funzionalità. È che l'estensione Azure Functions MCP sta diventando una scelta di piattaforma realistica per i team che vogliono ospitare capacità MCP su Azure senza costruire tutto da zero.

E per gli sviluppatori .NET, in particolare, l'esperienza continua a migliorare.
