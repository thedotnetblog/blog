La extensión Azure Functions MCP hace tiempo que pasó la fase de «mira, puedes exponer una herramienta».

Eso es lo que deja claro esta última actualización.

A estas alturas, la historia es mucho más amplia:

- herramientas
- recursos
- prompts
- MCP Apps
- autenticación integrada
- mejores APIs de configuración en .NET

Y eso cambia cómo veo la plataforma.

## La extensión madura de novedad de preview a material de construcción real

Los primeros anuncios de MCP trataban sobre todo de habilitar el protocolo. Útil, pero todavía bastante crudo.

Ahora la extensión está creciendo hacia algo más completo para equipos con mentalidad de producción:

- soporte más rico para primitivas
- mejor soporte de autenticación
- contenido y esquemas estructurados
- configuración .NET más natural con builder
- un camino más claro hacia la integración con Foundry

Eso es lo que quieres ver.

## Por qué Azure Functions encaja tan bien con MCP

Sigo pensando que Azure Functions es una de las opciones de hospedaje más prácticas para servidores MCP remotos.

Obtienes:

- hospedaje sin servidor
- ejecución escalable
- patrones familiares de triggers y bindings
- integración de identidad incorporada
- buena alineación con superficies de herramienta tipo API

Y con la extensión MCP, la distancia entre «tengo una función útil» y «tengo una superficie de herramientas descubrible para agentes» sigue reduciéndose.

## La historia del builder fluido en .NET es especialmente buena

Las adiciones de .NET me llamaron la atención porque continúan la tendencia hacia una configuración más expresiva dentro del código.

Poder declarar metadatos, esquemas, enlaces de UI y un comportamiento MCP más rico de forma fluida hace que la extensión se sienta más como una herramienta de desarrollo de primera clase y menos como una simple capa delgada de protocolo.

Esa es exactamente la dirección que quiero.

## Mi lectura

La verdadera historia aquí no es una sola función. Es que la extensión Azure Functions MCP se está convirtiendo en una opción de plataforma realista para los equipos que quieren alojar capacidades MCP en Azure sin construirlo todo desde cero.

Y para los desarrolladores .NET, en particular, la experiencia sigue mejorando.
