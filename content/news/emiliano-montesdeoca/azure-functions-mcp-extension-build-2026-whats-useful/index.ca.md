L'extensió Azure Functions MCP fa temps que ha superat la fase de «mira, pots exposar una eina».

Això és el que deixa clar aquesta última actualització.

A hores d'ara, la història és molt més àmplia:

- eines
- recursos
- prompts
- MCP Apps
- autenticació integrada
- millors API de configuració en .NET

I això canvia la manera com veig la plataforma.

## L'extensió madura de novetat de preview a material de construcció real

Els primers anuncis de MCP tractaven sobretot d'habilitar el protocol. Útil, però encara bastant cru.

Ara l'extensió està evolucionant cap a una cosa més completa per a equips orientats a producció:

- suport més ric per a primitives
- millor suport d'autenticació
- contingut i esquemes estructurats
- configuració .NET més natural amb builder
- un camí més clar cap a la integració amb Foundry

Això és el que vols veure.

## Per què Azure Functions encaixa tan bé amb MCP

Encara crec que Azure Functions és una de les opcions d'hostatge més pràctiques per a servidors MCP remots.

Obteniu:

- hostatge sense servidor
- execució escalable
- patrons familiars de triggers i bindings
- integració d'identitat integrada
- bona alineació amb superfícies d'eina tipus API

I amb l'extensió MCP, la distància entre «tinc una funció útil» i «tinc una superfície d'eines descobrible per als agents» continua reduint-se.

## La història del builder fluent en .NET és especialment bona

Les addicions de .NET m'han cridat l'atenció perquè continuen la tendència cap a una configuració més expressiva dins del codi.

Poder declarar metadades, esquemes, enllaços d'interfície d'usuari i un comportament MCP més ric d'una manera fluent fa que l'extensió sembli més una eina de desenvolupador de primera classe i menys un embolcall prim de protocol.

És exactament la direcció que vull.

## La meva lectura

La història real aquí no és una sola funcionalitat. És que l'extensió Azure Functions MCP s'està convertint en una opció de plataforma realista per a equips que volen allotjar capacitats MCP a Azure sense construir-ho tot des de zero.

I per als desenvolupadors .NET, especialment, l'experiència continua millorant.
