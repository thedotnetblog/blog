يواصل Azure DevOps MCP Server التحسن. تحديث أبريل الذي نشره Dan Hellem يغطي الخادمين المحلي والبعيد، وهناك إضافات مفيدة فعلًا هنا — خصوصًا إذا كنت تستخدم Copilot للتنقل في اللوحات والمستودعات.

## دعم استعلامات WIQL

الميزة الأبرز: أداة جديدة `wit_query_by_wiql` تتيح لك تشغيل استعلامات Work Item Query Language مباشرة من عميل MCP.

إذا كنت قد استخدمت Azure Boards لأي مدة، فأنت تعرف WIQL. إنها صيغة استعلام شبيهة بـ SQL لمهام العمل: `SELECT [System.Id], [System.Title] FROM WorkItems WHERE [System.AssignedTo] = @Me AND [System.State] = 'Active'`. وجود هذا كأداة MCP يعني أن جلسات Copilot يمكنها الآن سحب مجموعات دقيقة من مهام العمل من دون أن تضطر إلى التصفية يدويًا أو التنقل عبر طرق عرض اللوحات.

هناك تنبيه واحد: على خادم MCP البعيد، تتطلب هذه الأداة حاليًا راية ميزة **Insiders** أثناء التحقق من أداء الاستعلام على نطاق واسع. وستصل إلى الجميع عندما تبدو القياسات جيدة.

## رموز الوصول الشخصي على الخادم المحلي

يدعم خادم MCP المحلي الآن مصادقة PAT. قد يبدو هذا إصلاحًا صغيرًا لجودة الحياة، لكنه مهم فعلًا لسيناريوهات التكامل — خصوصًا عندما تشغّل خادم MCP في سياق لا تتوفر فيه مصادقة تفاعلية، أو عندما تتصل من عملاء خارجيين وأتمتة.

تتوفر خطوات الإعداد في [دليل البدء](https://github.com/microsoft/azure-devops-mcp/blob/main/docs/GETTINGSTARTED.md#-personal-access-token-pat).

## شروح MCP على الخادم البعيد

الشروح هي وسوم بيانات وصفية على أدوات MCP تخبر نماذج اللغة الكبيرة بكيفية استخدامها بأمان. أصبح Azure DevOps MCP Server يطبّق الآن الشروح على:

- **أدوات للقراءة فقط** — يعرف النموذج أنها آمنة للاستدعاء من دون تأكيد من المستخدم
- **أدوات مدمرة** — يعرف النموذج أن يكون حذرًا ويؤكد قبل المتابعة
- **أدوات مفتوحة العالم** — يفهم النموذج أن هذه قد تُرجع نتائج غير متوقعة

هذا أساس لثبات الوكلاء. من دون الشروح، يضطر النموذج إلى التخمين من اسم الأداة ما إذا كان من الآمن استدعاؤها. مع الشروح، يصبح السلوك واضحًا ويمكن للوكيل اتخاذ قرارات أفضل.

## توحيد أدوات الويكي

يبدأ الخادم البعيد في توحيد الأدوات المرتبطة في عدد أقل من الأدوات الأكثر قدرة. أدوات الويكي هي أول من يحصل على هذا التغيير:

| الأداة الجديدة | تستبدل |
|----------|----------|
| `wiki` (للقراءة فقط) | `wiki_get_page`, `wiki_get_page_content`, `wiki_list_pages`, `wiki_list_wikis`, `wiki_get_wiki` |
| `wiki_upsert_page` | `wiki_create_or_update_page` |

عدد أقل من الأدوات = أداء أفضل للنموذج. هذا نمط ثابت في تصميم خوادم MCP — مجموعات الأدوات الأصغر والأكثر تركيزًا تعمل بشكل أفضل لأن النموذج لا يحتاج إلى التفكير في أي من الأدوات الخمس المتشابهة الأسماء يختار.

## تجريبي: MCP Apps

هذا هو الإضافة الأكثر إثارة للاهتمام، ومن الواضح أنها تجريبية. MCP Apps هي سير عمل مُعبأة تعمل داخل بيئة خادم MCP:

```json
{
  "servers": {
    "ado": {
      "type": "stdio",
      "command": "mcp-server-azuredevops",
      "args": ["contoso", "-d", "core", "work", "work-items", "mcp-apps"]
    }
  }
}
```

المثال الأول هو `mcp_app_my_work_item` — تجربة مستقلة لمهام العمل تتيح لك عرضها وتصفيتها وتحريرها، من دون الحاجة إلى ربط عدة استدعاءات أدوات يدويًا.

الفكرة مقنعة: بدلًا من أن يستدعي وكيلك `wit_get_work_item` → `wit_list_work_items` → `wit_update_work_item` عبر عدة جولات، توفر MCP App واحدة سير العمل الكامل كوحدة واحدة منظمة وقابلة لإعادة الاستخدام. إعداد أقل، سلوك متسق، ومكونات أقل تحركًا.

## الخلاصة

ينضج Azure DevOps MCP Server بسرعة. دعم WIQL ومصادقة PAT مكسبان مباشران لأي شخص يستخدم Copilot مع Azure Boards. عمل الشروح يجعل الخادم البعيد أكثر أمانًا لحالات الاستخدام الوكيلة. وMCP Apps، رغم أنها تجريبية، تلمّح إلى الاتجاه القادم: من الأدوات الخام إلى سير العمل القابل للتركيب.

مفيد أن تتابع [الوثائق](https://learn.microsoft.com/en-us/azure/devops/mcp-server/remote-mcp-server) مع استمرار تطور الخادم البعيد.
