À première vue, PowerToys 0.100 ressemble à l'un de ces correctifs qu'on parcourt, qu'on approuve d'un hochement de tête, puis qu'on oublie.

Mais je pense qu'il y a ici une vraie histoire de développeur.

Non, ce n'est pas une version de framework. Et non, ce n'est pas directement du code d'application. Mais quand un outil que beaucoup de développeurs Windows gardent ouvert toute la journée reçoit une mise à niveau vers .NET 10, une Command Palette plus puissante et une meilleure ergonomie pour les extensions et les workflows, je pense qu'il mérite au moins un second regard.

## Le passage à .NET 10 est le signal discret

L'une des notes les plus intéressantes de cette version est que PowerToys est désormais passé à .NET 10.

Cela compte moins parce que les utilisateurs ressentiront directement le nom du runtime, et plus parce que cela reflète la confiance dans la plateforme et la modernisation continue d'une des suites d'utilitaires Windows les plus visibles de Microsoft.

Je fais toujours attention quand de vrais outils adoptent tôt le runtime le plus récent. Cela dit quelque chose sur la maturité de l'écosystème, la confiance dans les performances et l'orientation de l'énergie d'ingénierie interne.

## Command Palette devient toujours plus pertinente

L'histoire la plus visible pour l'utilisateur est probablement la nouvelle **Extension Gallery** et le support Dock amélioré dans Command Palette.

C'est intéressant parce que cela pousse PowerToys à devenir davantage qu'une simple collection d'utilitaires. Cela devient plutôt une surface de productivité personnalisable.

Pour les développeurs, c'est important quand on pense en termes de :

- actions rapides
- points de lancement personnalisés
- workflows multi-écrans
- tâches pilotées par des extensions

Ce n'est pas la même chose que les expériences de commande fortement centrées sur l'IA que l'on voit ailleurs, mais cela se situe dans un espace voisin : des outils qui réduisent la friction entre l'intention et l'action.

## Pourquoi je pense que cela reste à sa place sur ce blog

La raison pour laquelle je surveillerais ce genre de version est simple : une bonne expérience de développement ne dépend pas seulement du compilateur ou de l'IDE.

Elle dépend aussi des utilitaires autour de ton environnement quotidien.

Quand ces outils s'améliorent :

- les changements de contexte diminuent
- la configuration du poste de travail devient plus fluide
- les actions répétées s'accélèrent
- les options de personnalisation augmentent

Cela peut ne pas sembler spectaculaire, mais cela s'accumule avec le temps.

PowerToys 0.100 n'est pas une version incontournable pour chaque développeur .NET.
