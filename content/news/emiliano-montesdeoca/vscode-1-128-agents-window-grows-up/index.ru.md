Visual Studio Code 1.128 — значимый релиз не из-за одной убийственной функции, а потому что несколько изменений выравниваются вокруг единого направления: агент-ориентированная разработка внутри редактора становится структурированной, параллельной и операционно управляемой.

Оригинальный источник: https://code.visualstudio.com/updates/v1_128

Главное — более богатое multi-chat поведение в агентных host-сессиях, включая peer чаты, forks и одновременные обороты под одной родительской сессией. Это именно то, что нужно опытным разработчикам при исследовании альтернативных реализаций или разделении задач по путям верификации. Это отражает реальную инженерную работу, которая редко бывает линейной.

Мое мнение: это первый релиз VS Code, где Окно Агентов ощущается не как чат-панель, а как поверхность оркестрации рабочего пространства.

Быстрые чаты без выбранного рабочего пространства также важнее, чем кажутся. Они снижают трение для концептуальных или архитектурных вопросов, сохраняя привязанные к проекту сессии отдельными. Такое разделение может уменьшить беспорядок и сохранить целостность контекста для воркфлоу модификации кода.

Copilot Vision, достигший GA, — еще одна точка перегиба. Как только изображения и PDF становятся обычными входными данными для чата, задачи с интенсивной документацией и UI становятся значительно более плавными. Командам теперь стоит думать о мультимодальном контексте как о стандартной возможности, а не продвинутом дополнении.

Есть и практические платформенные последствия. Поддержка BYOK в сценариях агентного host, настраиваемые параметры семплирования модели и стандартные настройки утилитных моделей указывают на растущую зрелость корпоративного управления моделями. Организации со строгими требованиями к провайдерам теперь могут формировать поведение с более тонким контролем вместо универсальных настроек по умолчанию.

Рекомендации для команд, внедряющих 1.128:

Определите конвенции для ветвления и именования чатов в multi-chat сессиях, чтобы параллельное исследование не стало коммуникационным шумом. Поощряйте разработчиков держать один чат для реализации и один для тестов или анализа сбоев. Используйте быстрые чаты осознанно для вопросов, не связанных с репозиторием.

Если вы запускаете BYOK endpoint-ы, установите базовые профили температуры/top_p для каждого класса рабочей нагрузки и документируйте исключения. Также решите, должны ли утилитные потоки работать на Copilot-предоставленных или BYOK моделях, чтобы избежать случайных тихих разрывов в поведении.

Наконец, стратегически рассмотрите сочетания клавиш на уровне ОС. Возможность запускать команды VS Code системно может улучшить поток для продвинутых пользователей, но неуправляемое расползание горячих клавиш может навредить консистентности между командами.

VS Code 1.128 не просто добавляет функции. Он укрепляет механику агентного сотрудничества в реальных циклах разработки. Редакторы, которые победят в следующем цикле, будут теми, кто относится к взаимодействию с агентами как к примитивам воркфлоу первого класса, а не экспериментам на боковой панели. Этот релиз показывает, что VS Code понимает эту гонку.
