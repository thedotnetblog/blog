Visual Studio Code 1.128은 하나의 킬러 기능 때문에가 아니라 여러 변경이 하나의 방향으로 정렬되기 때문에 의미 있는 릴리스입니다: 에디터 내부의 에이전트 우선 개발이 구조화되고, 병렬화되며, 운영상 관리 가능해지고 있습니다.

원문: https://code.visualstudio.com/updates/v1_128

가장 눈에 띄는 것은 에이전트 호스트 세션의 **더 풍부한 멀티 채팅 동작**으로, 피어 채팅, 포크, 하나의 부모 세션 아래 동시 턴을 포함합니다. 이것은 대체 구현을 탐색하거나 검증 경로 간에 작업을 분할할 때 숙련된 개발자가 정확히 필요로 하는 것입니다. 드물게 선형적인 실제 엔지니어링 작업을 반영합니다.

내 의견: 이것은 Agents 창이 채팅 패널보다는 워크스페이스 오케스트레이션 표면처럼 느껴지기 시작하는 첫 번째 VS Code 릴리스입니다.

선택된 워크스페이스 없는 빠른 채팅도 보이는 것보다 더 중요합니다. 개념적 또는 아키텍처 질문에 대한 마찰을 낮추면서 프로젝트 바운드 세션을 별도로 유지합니다. 그 분리는 코드 수정 워크플로의 혼란을 줄이고 컨텍스트 무결성을 보존할 수 있습니다.

**Copilot Vision이 GA에 도달**한 것은 또 다른 변곡점입니다. 이미지와 PDF가 채팅의 정상적인 입력이 되면, 문서 중심 및 UI 중심 작업이 훨씬 더 유연해집니다. 팀은 이제 멀티모달 컨텍스트를 고급 추가 기능이 아닌 기본 기능으로 생각해야 합니다.

실용적인 플랫폼 영향도 있습니다. 에이전트 호스트 시나리오의 **BYOK 지원**, 구성 가능한 모델 샘플링 파라미터, 유틸리티 모델 기본값은 엔터프라이즈 모델 거버넌스의 성장하는 성숙도를 나타냅니다. 엄격한 공급자 요구사항이 있는 조직은 이제 모든 상황에 적용되는 하나의 기본값 대신 더 세밀한 제어로 동작을 형성할 수 있습니다.

### 1.128 도입 팀을 위한 권장사항

- **멀티 채팅 세션에서 채팅 분기 및 명명에 대한 규칙을 정의**하여 병렬 탐색이 대화형 노이즈가 되지 않도록 하세요.
- **개발자가 구현용 채팅 하나, 테스트 또는 실패 분석용 채팅 하나를 유지하도록 장려**하세요.
- **리포지토리 관련 없는 질문에는 빠른 채팅을 의도적으로 사용**하세요.
- **BYOK 엔드포인트를 운영한다면**, 워크로드 클래스별로 기준 temperature/top_p 프로필을 설정하고 예외를 문서화하세요.
- **유틸리티 흐름이 Copilot 제공 또는 BYOK 모델에서 실행되어야 하는지 결정**하여 우발적인 무음 동작 격차를 피하세요.
- **OS 수준 단축키를 전략적으로 고려**하세요. 시스템 전체에서 VS Code 명령을 트리거할 수 있으면 파워 유저의 흐름을 개선할 수 있지만, 관리되지 않은 키바인딩 확산은 팀 간 일관성을 해칠 수 있습니다.

## 결론

VS Code 1.128은 단순히 기능을 추가하지 않습니다. 실제 개발 루프에서 에이전트 협업의 메커니즘을 강화합니다. 다음 주기에서 승리하는 편집기는 에이전트 상호 작용을 사이드바 실험이 아닌 **일급 워크플로 프리미티브**로 취급하는 편집기입니다. 이 릴리스는 VS Code가 그 경쟁을 이해하고 있음을 보여줍니다.
