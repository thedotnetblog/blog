Visual Studio Code 1.128 は、ひとつのキラー機能のためではなく、複数の変更が単一の方向性に沿っているため、意味のあるリリースである: エディタ内のエージェントファースト開発が、構造化され、並列化され、運用上管理可能になりつつある。

オリジナルソース: https://code.visualstudio.com/updates/v1_128

特筆すべきは、エージェントホストセッションにおける**よりリッチなマルチチャット動作**であり、ピアチャット、フォーク、単一の親セッション下での並行ターンを含む。これはまさに、代替実装を探索したり、検証パス間でタスクを分割したりするときに経験豊富な開発者が必要とするものである。それは、めったに線形ではない実際のエンジニアリング作業を反映している。

私の見解: これは、Agents ウィンドウがチャットパネルというよりもワークスペースオーケストレーションサーフェスのように感じられる最初の VS Code リリースである。

選択されたワークスペースなしのクイックチャットも、見た目以上に重要である。これらは、プロジェクトバインドセッションを明確に区別しながら、概念的またはアーキテクチャ上の質問への摩擦を減らす。その分離は、混乱を減らし、コード修正ワークフローのコンテキスト整合性を維持するのに役立つ。

**Copilot Vision の GA 到達**ももうひとつの変曲点である。画像と PDF がチャットへの通常の入力になると、ドキュメント多用および UI 多用のタスクが大幅に流動的になる。チームは今やマルチモーダルコンテキストを高度なアドオンではなくデフォルト機能として考えるべきである。

実用的なプラットフォームの影響もある。エージェントホストシナリオにおける **BYOK サポート**、設定可能なモデルサンプリングパラメータ、ユーティリティモデルのデフォルトは、エンタープライズモデルガバナンスの成熟度の高まりを示している。厳格なプロバイダー要件を持つ組織は、一律のデフォルトではなく、より細かい制御で動作を形成できる。

### 1.128 を採用するチームへの推奨

- **マルチチャットセッションでのチャット分岐と命名の規約を定義し**、並行探索が会話ノイズにならないようにする。
- **開発者に実装用のチャットと、テストまたは障害分析用のチャットを別々に保つことを推奨する。**
- **クイックチャットはリポジトリ外の質問に意図的に使用する。**
- **BYOK エンドポイントを実行している場合**、ワークロードクラスごとにベースライン temperature/top_p プロファイルを確立し、例外を文書化する。
- **ユーティリティフローを Copilot 提供モデルと BYOK モデルのどちらで実行するかを決定し**、意図しないサイレント動作ギャップを避ける。
- **OS レベルのショートカットを戦略的に検討する。** システム全体で VS Code コマンドをトリガーできることはパワーユーザーのフローを改善できるが、管理されていないキーバインディングの散乱はチーム間の一貫性を損なう可能性がある。

## 結論

VS Code 1.128 は機能を追加するだけではない。実際の開発ループにおけるエージェントコラボレーションのメカニズムを強化する。次のサイクルで勝つエディタは、エージェントインタラクションをサイドバーの実験ではなく、**ファーストクラスのワークフロープリミティブ**として扱うものである。このリリースは、VS Code がそのレースを理解していることを示している。
